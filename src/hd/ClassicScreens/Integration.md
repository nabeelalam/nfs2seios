# Classic screens source package

Portable source staging for Load/Save, Records, Statistics, Results, Victory and Credits. Generation is opt-in and the default performance build remains unchanged. The maintained source includes the dynamic menu, post-race, scrolling-credit and child-dialog rendering paths.

`consolidate_classic_screens.py` accepts an explicit source checkpoint, override directories and fallback dependency directories. It refuses existing outputs, removes experimental relative includes and sends every `*Data.h` payload into a separate ignored `.build` directory. No original game assets or installed font files belong in this source folder. `PRIVATE_ASSETS.json` lists the nine required header names; it is an input inventory, not a publication authorization. Reviewed distributable headers now live in `assets/hud/classic-screens`, with exact identities and license notices in `APPROVED_ASSETS.json`. Public CI requires that manifest and every named input to be tracked regular files. Generators copy only the named headers into ignored generated `hd/ClassicScreens/private` input. Explicit private header directories remain available for local artwork work.

Renderer integration: the completed combined overlay is `RendererHooks.inc`; it retains the original existing BackgroundSceneRenderer machinery and adds the six screen lifetimes/native-pass hooks. Use it in place of the prior generated BackgroundSceneRenderer overlay, with both `src` and `src/hd` include directories. Do not include a second copy alongside the prior overlay. This staging does not change default renderer activation.

Generated source integration: Run `scripts/classic_screens_hooks.py --source-dir <prepared engine units> --output <new private directory>` to apply Load/Save, font lifetime, Records, Statistics, Results, Victory, Credits and child-dialog insertions while carrying every untouched Methods unit forward. Source includes use `hd/ClassicScreens/`. The scripts preserve original calls; mismatched source anchors fail. The Results stage includes the accepted source-driven header-band instrumentation.

Both `prepare_full_mapped.py` and `prepare_renderer.py` expose `--classic-screens --classic-assets-dir <private headers>`. Both source and renderer generation require a new explicit `--output-dir` for classic screens. Renderer opt-in rejects the accepted default `.build/renderer` destination. The source pipeline includes maintained `classic_screens/loadsave_hooks.py` and `font_lifetime_hooks.py` modules for exact Load/Save insertion and persistent font ownership. Runtime feature environment gates are retained; generation does not silently activate them. No compilation or physical-device validation is implied by this source package. Child Load/Save dialogs share the existing source owner and are integrated last in the pipeline.

Child-dialog materials are integrated after the child source scopes. Exact source bounds drive native beveled surfaces, source selection style drives row highlights, and the original caret remains above those surfaces. The accepted SE emblem provider is retained. The renderer retains the qualified HD parent while the original game opens and closes the child. Child animation/text and restoration are reviewed as part of the combined UI checkpoint; individual publication messages do not establish visual correctness.

Build selection uses CMake cache paths `NFS_FULL_MAPPED_ENGINE_DIR` and `NFS_RENDERER_SOURCE_DIR`. Point these at the separately prepared classic-screen outputs. Their defaults remain the standard prepared engine and renderer.

For the dedicated UI app build, set `NFS_CLASSIC_UI=ON` after preparing both classic inputs and pinning the artwork pack. Successful artwork activation then enables the classic screen lifetimes before the game worker starts. The default build remains unchanged. Dynamic glyph atlases use League Gothic and Michroma under the included SIL OFL license texts; accepted finite word artwork remains separate.

## Personal artwork and delivery

`cmake/BundledOwnedArtwork.cmake` supports a separately authenticated `classic-ui.ownedz` resource. The loader reconstructs its omitted original headers only from the player-supplied game archive and validates the complete artwork identity before activating the UI. Neither original game data nor the private template is published by the source workflow.

For the public build, `NFS_CLASSIC_DEFER_OWNER_TEMPLATE=ON` deliberately omits that template. The resulting unsigned ARM64 IPA is labelled a base requiring personal artwork; public release publication is refused. `scripts/inject_personal_artwork.py` adds the separately retained, exact template to a verified unsigned base without changing existing executable or resource bytes. Its output is for private personal delivery and still requires personal signing and physical iPad verification. Normal SideStore updates preserve the app identity.

Keep the original performance branch independent: classic generation uses separate prepared engine and renderer outputs, enabled explicitly through `NFS_FULL_MAPPED_ENGINE_DIR`, `NFS_RENDERER_SOURCE_DIR` and `NFS_CLASSIC_UI`. Runtime menu improvements do not replace the original game simulation, control settings, saves or supplied assets.

The first combined preview has passed the gated Linux checks and Apple ARM64 Release build. The personal finishing step preserves the existing executable/resource bytes while adding the authenticated artwork resource. Local chooser animation, cancellation and final HD parent restoration were observed. Physical iPad UI, race/post-race coverage and battery acceptance remain open; the UI branch has not been merged into main. See `evidence/hd-classic-ui-apple-preview.json` for the exact build provenance.
