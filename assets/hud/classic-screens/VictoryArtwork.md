# Victory artwork archive

The winner pictures form a separate source-bound screen set: a trophy base and fifteen car variants, each with 4:3 and 16:9 artwork. A production resource requires all 32 reviewed images. The current real-artwork resource is an explicitly marked 16-image 4:3 preview; it is not installed in the app.

`scripts/victory_image_pack.py` accepts a private manifest of image identities, original source hashes and authored master hashes. It retains the masters' exact pixels and stores opaque RGB PNG row-filter streams compressed with zlib. This reuses the slideshow encoder and bounded pixel reconstruction. No scaling, quantization or color remapping occurs in this packaging step. Every metadata entry binds one compressed chunk and its reconstructed RGBA digest.

The archive header is `NFSVIC01`, version 1, count, preview flag and 128-byte record size. Each record contains aspect, scene index, dimensions, predictor, compressed size, offset, RGBA SHA-256, compressed-chunk SHA-256 and original-source SHA-256. Scene zero is the backdrop; scenes one through fifteen follow the original car-index table. Production records are contiguous and ordered as sixteen 4:3 scenes followed by sixteen 16:9 scenes. The original-source association must match across aspects.

`VictoryArtworkArchive.h` accepts an expected file size and metadata digest, validates bounds and the complete table, and retains only metadata. Each `load` call requires the matching original source identity, reads one bounded chunk and validates its compressed and decoded hashes before changing the caller's output. Unrelated images remain compressed on disk. The archive reader does not prove a live game owner, authorize a renderer pass or install artwork. Original backdrop/photo lookup, draw order and frame lifetime still require a separate source-bound integration.

The slideshow's public `inflatePixels` entry retains its existing 4:3-only contract. Adaptive scene packs explicitly call `inflateCanvasPixels`, which allows only bounded 4:3 or 16:9 canvases.

It needs explicitly supplied generated fixtures, so default CTest does not depend on private artwork. `VictoryArtProvider.h/.cpp` provides a C interface for registering the pinned archive and acquiring one selected image. Registration checks metadata and all finite original-source associations without decoding pixels. Production admission requires32images; diagnostic preview admission is explicit. Acquisition requires the independently authenticated original-source digest as well as aspect/image identity. It retains a single decoded-image cache, reuses its owned bytes for repeated requests, and preserves the previous cache and caller output on failed requests.

Each acquired view owns immutable pixels through paired retain/release callbacks. Old views remain readable across clear/reload, but consumers must check their generation against the currently published provider generation before publishing them. Image identity is stable across reload; generation is therefore part of the renderer cache key. Multiple outstanding views and in-flight decode buffers mean one cached image is not a peak-memory claim.
