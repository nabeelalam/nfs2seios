# Compact Player sidebar words

These are two fixed lowercase text graphics, “player one” and “player two”, rendered locally in the classic typeface used by the revised Player menu. The source contains no font file, alphabet or original game pixels. The complete-word graphics route is described in the [Microsoft font FAQ](https://learn.microsoft.com/en-us/typography/fonts/font-faq#redistribution-and-extended-rights).

The original game still resolves, measures and draws its caption normally. The immutable software packet, original pixels, font provider and geometry remain source evidence. A separate display adapter may use these two images only when a genuine retained compact-caption proof matches the Player, exact packet, owner, archive, serial, lifetime, text, original measurement and clip. Missing optional metadata retains the prior software display; invalid supplied metadata declines. Historical caption evidence alone does not grant live scene or GPU authority.

The existing captions have source size 18 and a display baseline at original Y + 24. The authored display uses the chosen typeface at logical size 24 with the same light stroke treatment as the Player body text. The images are 272×128 and 280×128 at four raster pixels per original UI unit. Their destinations remain [100,198,168,230] and [98,234,168,266], preserving the original right edge and original text width. Visible ink fits strictly inside those horizontal areas. The original initial slide-in and later cached scene routes share the same retained artwork.

`player-caption-word-art.json` is a bounded, independently pinned two-image source. `generate_player_caption_words.py` verifies exact identities, dimensions, rectangles, alpha runs and decoded RGBA digests before generating the C-compatible data and identity headers. Neither generation nor runtime needs Haettenschweiler installed. The source contains complete image alpha only; RGB is white, including transparent pixels.

A dedicated Player-only GPU word view is separate from `FontCatalog`. It validates the fixed identities independently, copies the borrowed image during synchronous preparation, and retains only owned GPU resources. Frame schema 2 keeps the existing software caption view and appends the explicit word image. Zero word views preserve legacy display; malformed nonzero views decline. The dedicated texture/shader follows existing context ownership, staging, state restoration and retirement rules. Other font roles, artwork and physical-device acceptance are separate work.
