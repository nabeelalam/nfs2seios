# Classic lettering for the remaining menu words

Fifty finite whole-word images bring the catalogued Location, Setup, Opponents and Options body text and values into the same classic family as Main and Player. The images use lighter Haettenschweiler lettering, authored locally, and preserve each original allocation, baseline, glyph partition, shadow and interaction area. Narrow original text areas constrain the width of their individual image; the menu geometry is unchanged.

The source is three bounded `remaining-menu-word-art-*.json` files with sixteen, seventeen and seventeen images. Each record pins its text, exact allocation/crop, decoded RGBA digest, approved family use and alternating alpha run lengths/values. No font file, reusable alphabet, original game pixels, captures or internal paths are included. Build hosts need no proprietary font. See the [Microsoft font FAQ](https://learn.microsoft.com/en-us/typography/fonts/font-faq#redistribution-and-extended-rights) for graphics produced with fonts.

All three selected source files are authenticated before decoding or writing pixels. The override runs after the independent eight Main, thirty Player/shared body and four uppercase heading/button images, leaving those accepted images unchanged. Full generation checks every affected normal/shadow placement against the actual original output positions and glyph contexts. Two Setup images also supply scaled Main summaries: their complete forty-two-row extension, output scales and four additional placements are checked explicitly. In total this override covers fifty catalogued uses, two summary roles and 104 placements.

The eight-MiB GPU atlas and complete word layout are unchanged. The authored atlas requires 79 run-aligned source chunks; a shared 96-part maximum bounds generation, renderer copying and layout-only inventory. Every generated file remains below the existing 1 MiB gate. More source encoding bytes do not increase this atlas's GPU allocation. The chunk tests cover the accepted maximum and reject excess bytes, duplicate/out-of-order parts, foreign includes and excess part counts.

Layout-only generation authenticates these same selected sources, placements and metadata alongside all generated headers and catalogs. Historical packing tests regenerate the old SVG images before checking the unchanged packing recipe. The previous OFL SVGs and catalog font names describe that historical base recipe; the final generated pixels come from these fixed word images and the earlier finite overrides.

These four menu catalogs now have no remaining historical word allocation after all fixed-art overrides. Dynamic/software text roles, other screens, artwork, HUD and physical iPad acceptance remain separate work. Local source and renderer checks do not establish device FPS or battery performance.
